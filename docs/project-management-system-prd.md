# 项目管理系统需求文档

## 1. 文档基础信息

| 项目 | 内容 |
| --- | --- |
| 系统名称 | 项目管理系统 |
| 文档类型 | 产品需求文档（PRD） |
| 文档版本 | V1.0 |
| 文档语言 | 中文 |
| 适用对象 | 产品、设计、研发、测试、实施 |

## 2. 需求概述

### 2.1 需求背景

当前各个产品项目的文件资料（如产品原型、需求文档等）分散在不同项目、不同存储位置及不同管理方式中，缺少统一规范，容易造成以下问题：

- 项目资料分散，查找成本高；
- 不同项目的文件管理方式不统一，维护困难；
- 文档版本不清晰，容易出现误用、漏用；
- 管理过程混乱，难以支撑后续项目沉淀和复用。

因此，需要建设一套统一的项目管理系统，对项目基础信息及需求文档进行集中管理。

### 2.2 建设目标

- 建立统一的项目资料管理入口；
- 规范项目基础信息和需求文档的维护方式；
- 支持项目信息的新增、查询、编辑、删除；
- 支持需求文档的集中查看、上传、更新、下载、删除；
- 提供基础登录鉴权能力，保证系统仅限授权用户访问。

### 2.3 适用范围

本期需求覆盖以下范围：

1. 系统菜单与页面框架；
2. 项目概况管理；
3. 需求文档管理；
4. 登录、退出与登录态维持。

## 3. 用户角色说明

当前版本仅定义 1 类系统用户：

| 角色 | 账号 | 昵称 | 权限说明 |
| --- | --- | --- | --- |
| 系统管理员 | admin | 系统管理员 | 可登录系统并使用全部功能 |

> 说明：本期未要求细分多角色权限，默认登录成功后可访问系统内全部菜单与操作。

## 4. 系统整体结构

### 4.1 菜单结构

系统采用二级菜单结构，菜单在左侧边栏展示，页面内容在右侧标签页区域展示。

菜单结构如下：

- 一级菜单：项目管理
  - 二级菜单：项目概况
  - 二级菜单：需求文档管理

### 4.2 页面布局要求

1. 左侧为侧边栏菜单区域，支持折叠与展开；
2. 右侧为内容展示区域；
3. 打开的菜单页面以标签页形式在右侧展示；
4. 标签页名称取对应二级菜单名称；
5. 用户可在不同标签页之间切换查看页面内容。

## 5. 功能需求

## 5.1 登录与退出

### 5.1.1 功能目标

用户必须先登录后访问系统；登录后支持查看当前登录用户信息，并可主动退出登录。

### 5.1.2 登录页面

登录页面需包含以下内容：

- 账号输入框
- 密码输入框
- 登录按钮

### 5.1.3 预置账号信息

| 项目 | 内容 |
| --- | --- |
| 登录账号 | admin |
| 登录密码 | 12345 |
| 账号昵称 | 系统管理员 |

### 5.1.4 业务规则

1. 用户输入正确账号和密码后，方可进入系统首页；
2. 若账号或密码错误，应提示登录失败；
3. 用户未登录时，不可访问系统功能页面；
4. 登录状态维持 5 小时；
5. 登录成功后，系统右上角展示头像与昵称；
6. 头像默认取昵称首个字符；
7. 点击头像后弹出下拉菜单，菜单项为“退出登录”；
8. 点击“退出登录”后，用户退出当前登录状态并返回登录页面。

### 5.1.5 验收标准

- 正确输入 `admin / 12345` 可登录；
- 登录后页面右上角展示“系统管理员”及默认头像；
- 点击退出登录后返回登录页；
- 超过 5 小时后登录态失效，需要重新登录。

## 5.2 菜单展示功能

### 5.2.1 功能目标

通过统一的系统框架，承载项目管理相关功能页面。

### 5.2.2 功能要求

1. 菜单采用二级结构；
2. 一级菜单“项目管理”在侧边栏展示；
3. 二级菜单“项目概况”“需求文档管理”在一级菜单下展示；
4. 侧边栏支持折叠与展开；
5. 点击二级菜单后，在右侧以标签页形式打开对应页面；
6. 标签页标题为二级菜单名称。

## 5.3 项目管理 -> 项目概况

### 5.3.1 功能目标

以列表形式统一维护项目的基础信息，并作为需求文档管理的入口之一。

### 5.3.2 页面组成

项目概况页面由以下部分组成：

1. 查询区域；
2. 操作按钮区域；
3. 项目列表表格区域；
4. 分页区域。

### 5.3.3 列表展示要求

项目信息以表格形式分页展示，字段如下：

| 字段 | 说明 |
| --- | --- |
| 项目名称 | 项目标识名称 |
| 版本号 | 项目当前版本号 |
| 项目经理 | 项目负责人 |
| 需求部门 | 提出需求的部门 |
| 描述 | 项目或需求简介 |
| 需求文档 | 文档查看入口 |
| 操作 | 修改、删除 |

### 5.3.4 查询功能

#### 查询条件

支持根据以下字段进行模糊搜索：

- 项目名称
- 项目经理
- 版本号
- 需求部门

#### 交互要求

1. 查询区域位于表格上方；
2. 提供查询按钮；
3. 支持按照输入条件进行模糊匹配；
4. 查询结果刷新当前表格数据；
5. 若无匹配结果，表格显示空状态。

### 5.3.5 新增项目

#### 入口要求

在表格上方提供“新增”按钮。

#### 交互要求

1. 点击“新增”后，弹出项目录入对话框；
2. 对话框内支持录入项目基础信息；
3. 需求文档通过上传文件方式录入；
4. 已上传的需求文档以标签块形式展示；
5. 提交成功后，关闭对话框并刷新项目列表。

#### 录入字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 项目名称 | 是 | 项目标识名称 |
| 版本号 | 是 | 原始需求中“项目版本/版本号”表述重复，本文统一为“版本号” |
| 项目经理 | 是 | 项目负责人 |
| 需求部门 | 否 | 需求归属部门 |
| 描述 | 否 | 项目或需求描述 |
| 需求文档 | 否 | 通过文件上传录入，可上传后展示为标签块 |

### 5.3.6 修改项目

#### 入口要求

在表格“操作”列提供“修改”按钮。

#### 交互要求

1. 点击“修改”后，弹出项目编辑对话框；
2. 对话框展示当前项目已录入的信息；
3. 需求文档以标签块形式展示当前已上传内容；
4. 用户修改并提交成功后，刷新项目列表。

### 5.3.7 删除项目

#### 入口要求

在表格“操作”列提供“删除”按钮。

#### 交互要求

1. 点击“删除”后，弹出确认对话框；
2. 提示用户是否确认删除当前项目；
3. 用户确认后才执行删除；
4. 删除成功后刷新项目列表。

### 5.3.8 需求文档跳转

项目概况列表中的“需求文档”列，需要提供对应文档查看入口。

#### 交互要求

1. 用户点击文档查看入口后，跳转至“项目管理 -> 需求文档管理”；
2. 跳转后需自动定位到当前项目对应的需求文档目录；
3. 用户可直接在需求文档管理页面查看该项目/版本下的文档内容。

### 5.3.9 验收标准

- 项目列表可分页展示；
- 可完成新增、查询、修改、删除操作；
- 必填字段未填写时不可提交；
- 删除前有确认提示；
- 点击需求文档入口后可准确跳转到目标目录。

## 5.4 项目管理 -> 需求文档管理

### 5.4.1 功能目标

集中展示并管理各项目版本下的需求文档，支持查看、预览、下载、删除、更新和上传。

### 5.4.2 页面组成

需求文档管理页面包含两个模块：

1. 左侧：需求文档目录树；
2. 右侧：当前选中目录对应的文档表格/空状态区域。

### 5.4.3 目录树展示

目录树结构为：

`项目名称 -> 版本号 -> 需求文档`

#### 展示规则

1. 左侧以树形结构展示项目文档目录；
2. 第一层为项目名称；
3. 第二层为版本号；
4. 第三层为该版本下的需求文档；
5. 用户点击某一目录节点后，右侧刷新显示该目录下的文档内容。

### 5.4.4 文档表格展示

当当前目录下存在文档时，右侧展示文档列表表格。

#### 表格字段

| 字段 | 说明 |
| --- | --- |
| 文档名称 | 文件名称 |
| 项目名称 | 所属项目 |
| 版本号 | 所属版本 |
| 项目经理 | 项目负责人 |
| 需求部门 | 需求归属部门 |
| 上传人 | 当前文档上传人员 |
| 更新时间 | 最近更新时间 |
| 操作 | 预览、下载、删除、更新 |

### 5.4.5 文档预览

#### 入口要求

在表格“操作”列提供“预览”按钮。

#### 交互要求

1. 点击“预览”后，在右侧窗口弹出文件预览区域；
2. 支持以下格式预览：
   - rp
   - Excel
   - Word
   - html
   - ppt
   - pdf
   - zip
3. 若文件格式不支持预览，则提示：
   - `不支持当前文件格式预览，请下载后在本地打开`

### 5.4.6 文档下载

#### 入口要求

在表格“操作”列提供“下载”按钮。

#### 交互要求

1. 点击“下载”后，直接将文件下载到本地；
2. 下载完成后不影响当前页面状态。

### 5.4.7 文档删除

#### 入口要求

在表格“操作”列提供“删除”按钮。

#### 交互要求

1. 点击“删除”后，弹出确认对话框；
2. 提示用户是否确认删除当前文件；
3. 用户确认后方可执行删除；
4. 删除成功后刷新当前文档表格。

### 5.4.8 文档更新

#### 入口要求

在表格“操作”列提供“更新”按钮。

#### 交互要求

1. 点击“更新”后，可重新选择本地文件；
2. 新上传文件替代当前文件；
3. 更新完成后刷新当前文档表格展示。

### 5.4.9 空状态与上传

当当前目录下没有文档时，右侧需展示空状态。

#### 展示要求

1. 显示文案：`当前目录下无需求文档`
2. 在空状态区域下方提供“立即上传”按钮

#### 交互要求

1. 点击“立即上传”后，可选择本地文件上传至当前目录；
2. 上传成功后，刷新当前文档表格展示。

### 5.4.10 验收标准

- 左侧目录树可按“项目名称 -> 版本号 -> 需求文档”结构展示；
- 选中目录后，右侧正确展示对应文档列表；
- 支持预览、下载、删除、更新操作；
- 删除前有确认提示；
- 无文档时展示空状态及“立即上传”按钮；
- 从项目概况页面跳转进入后，可定位到准确目录。

## 7. 业务规则汇总

1. 系统仅允许登录后访问；
2. 登录态有效期为 5 小时；
3. 项目概况页面支持项目信息的增删改查；
4. 项目名称、版本号、项目经理为必填；
5. 项目删除与文档删除均需二次确认；
6. 项目概况中的文档入口需与需求文档管理页面联动；
7. 文档管理支持上传、更新、删除、下载、预览；
8. 不支持预览的文件格式需给出统一提示文案。

## 8. 非功能需求

### 8.1 易用性

- 页面布局清晰，操作入口明确；
- 表格、按钮、对话框的交互保持一致；
- 空状态、异常状态需有明确提示。

### 8.2 安全性

- 未登录用户不可访问系统页面；
- 退出登录后需清除当前登录态；
- 登录信息需受控校验。

### 8.3 可维护性

- 项目基础信息与文档信息需建立清晰关联；
- 菜单、项目、文档模块建议采用可扩展结构设计，便于后续增加更多项目管理能力。

## 10. 待确认事项

以下内容在原始需求中未完全明确，建议在进入设计或开发前补充确认：

1. 一个项目版本下是否允许上传多个需求文档；
2. “需求文档”列在项目概况页的展示样式，是固定“查看入口”还是展示具体文档名称；
3. 各类文件的大小限制、数量限制、命名规则是否需要控制；
4. 预览能力中 rp、Office、zip 文件的预览技术方案与兼容范围；
5. 是否需要记录文档历史版本，当前需求仅描述“更新替代当前文件”；
6. 是否需要新增项目创建人、创建时间、更新时间等审计字段；
7. 后续是否需要扩展为多账号、多角色权限体系。
