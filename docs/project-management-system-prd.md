# 项目管理系统需求文档

## 1. 文档概述

### 1.1 文档名称
项目管理系统需求文档

### 1.2 系统名称
项目管理系统

### 1.3 文档目的
基于当前整理的业务诉求，明确项目管理系统的建设背景、功能范围、页面结构、交互规则及业务约束，为后续产品设计、UI 设计、研发实现和测试验收提供统一依据。

### 1.4 适用对象
- 产品经理
- UI/UX 设计师
- 前端开发
- 后端开发
- 测试人员
- 项目干系人

## 2. 需求背景

当前各产品项目相关文件，如产品原型、需求文档等，分散存放在不同项目、不同文件目录或不同管理方式中，缺乏统一规范，容易造成以下问题：
- 文件存储路径不统一，查找成本高；
- 文档管理规则不一致，容易出现遗漏、重复或版本混乱；
- 项目资料难以集中维护，不利于跨团队协作；
- 文档更新与归档流程不清晰，影响项目推进效率。

因此，需要建设一套统一的项目管理系统，对项目基础信息及需求文档进行集中管理，实现项目资料标准化、可查询、可维护、可追溯。

## 3. 建设目标

- 统一管理各产品项目的基础信息；
- 统一管理项目对应的需求文档及目录结构；
- 支持项目信息和文档的新增、查询、修改、删除等常用操作；
- 支持需求文档的预览、下载、更新和删除；
- 通过登录态控制系统访问权限，保证数据的基本安全性；
- 提升项目资料管理效率，降低因文档分散导致的沟通和维护成本。

## 4. 用户角色

当前阶段系统仅定义一个默认管理账号，用于登录并访问系统全部功能。

### 4.1 默认账号信息
- 登录账号：admin
- 登录密码：12345
- 账号昵称：系统管理员

### 4.2 角色能力
- 访问项目管理相关全部页面；
- 管理项目概况信息；
- 管理需求文档目录及文档内容；
- 执行登录、退出登录操作。

## 5. 功能范围

本期功能范围包括：
- 菜单展示功能；
- 项目概况管理；
- 需求文档管理；
- 登录与退出功能。

不在本期范围内的能力包括但不限于：
- 多角色权限管理；
- 用户注册、找回密码、修改密码；
- 审批流；
- 消息通知；
- 项目进度、任务、甘特图等高级项目管理能力。

## 6. 信息架构与页面结构

## 6.1 菜单层级
系统采用二级菜单结构。

- 一级菜单：项目管理
- 二级菜单：
  - 项目概况
  - 需求文档管理

## 6.2 页面布局
- 左侧为系统侧边栏，用于展示一级菜单及二级菜单；
- 侧边栏支持折叠与展开；
- 右侧为内容区；
- 打开的菜单页面在右侧以标签页形式展示；
- 标签页名称取对应二级菜单名称；
- 用户可通过切换标签页访问不同已打开页面内容。

## 7. 详细功能需求

## 7.1 菜单展示功能

### 7.1.1 功能说明
系统通过左侧侧边栏展示菜单结构，支持用户快速进入项目管理相关页面。

### 7.1.2 功能要求
1. 系统采用二级菜单结构；
2. 当前仅配置一个一级菜单“项目管理”；
3. 二级菜单包括“项目概况”和“需求文档管理”；
4. 左侧侧边栏支持展开和折叠；
5. 用户点击二级菜单后，在右侧内容区打开对应页面；
6. 页面以标签页形式展示，标签名与二级菜单名称一致；
7. 当同一菜单已打开时，再次点击应定位至已打开标签页，避免重复打开。

## 7.2 项目管理 -> 项目概况

### 7.2.1 功能说明
用于统一维护项目的基础信息及与项目关联的需求文档入口。

### 7.2.2 页面布局
页面主要由以下区域组成：
- 查询区；
- 操作按钮区；
- 项目概况列表区；
- 新增/编辑弹窗；
- 删除确认弹窗。

### 7.2.3 列表展示要求
1. 项目信息列表以表格形式分页展示；
2. 列表字段包括：
   - 项目名称
   - 版本号
   - 项目经理
   - 需求部门
   - 描述
   - 需求文档
   - 操作
3. 每条记录单独展示；
4. 列表应支持分页切换；
5. “需求文档”列需提供查看入口；
6. “操作”列需提供“修改”和“删除”按钮。

### 7.2.4 查询功能
1. 在表格上方提供独立查询按钮及查询条件输入区域；
2. 支持按以下字段进行模糊搜索：
   - 项目名称
   - 项目经理
   - 版本号
   - 需求部门
3. 用户输入条件后点击查询，系统刷新列表结果；
4. 当查询条件为空时，展示全部项目数据。

### 7.2.5 新增项目
1. 在表格上方提供“新增”按钮；
2. 点击后弹出项目信息录入对话框；
3. 对话框需包含以下录入项：
   - 项目名称
   - 项目版本
   - 项目经理
   - 需求部门
   - 描述
   - 需求文档
4. 其中以下字段为必填：
   - 项目名称
   - 项目版本
   - 项目经理
   - 版本号
5. 需求文档通过上传文件方式录入；
6. 已上传的需求文档在弹窗内以标签块形式展示；
7. 用户提交成功后，刷新项目概况列表。

> 说明：原始需求中同时出现“项目版本”和“版本号”两个表述。为避免歧义，建议研发设计时统一为同一业务字段，并在页面文案层面保持一致。

### 7.2.6 修改项目
1. 列表“操作”列提供“修改”按钮；
2. 点击后弹出编辑对话框；
3. 对话框展示该项目当前已录入的信息；
4. 需求文档仍以标签块形式展示；
5. 用户可修改项目信息并重新上传需求文档；
6. 保存成功后刷新项目概况列表。

### 7.2.7 删除项目
1. 列表“操作”列提供“删除”按钮；
2. 点击删除后弹出确认对话框；
3. 对话框提示用户是否确认删除；
4. 用户确认后才执行删除；
5. 删除成功后刷新项目概况列表。

### 7.2.8 需求文档跳转
1. 项目概况列表中，每条记录的“需求文档”列提供文档查看入口；
2. 用户点击后，系统跳转至二级菜单“项目管理 -> 需求文档管理”；
3. 跳转后需自动定位到该项目对应版本下的准确需求文档目录；
4. 右侧文档表单区域同步展示该目录下文档数据。

## 7.3 项目管理 -> 需求文档管理

### 7.3.1 功能说明
用于按“项目名称 -> 版本号 -> 需求文档”层级统一管理项目需求文档。

### 7.3.2 页面布局
页面包含两个模块：
- 左侧：需求文档目录树；
- 右侧：文档表单区。

### 7.3.3 目录树展示要求
1. 目录树按以下层级结构展示：
   - 项目名称
   - 版本号
   - 需求文档
2. 用户点击目录树节点后，右侧展示当前选中目录对应的文档内容；
3. 从项目概况页跳转进入时，应自动选中目标目录节点。

### 7.3.4 文档表单展示逻辑

#### 7.3.4.1 当前目录下存在文档时
右侧展示当前目录下的文档列表表格。

表格字段包括：
- 文档名称
- 项目名称
- 版本号
- 项目经理
- 需求部门
- 上传人
- 更新时间
- 操作

“操作”列需提供以下按钮：
- 预览
- 下载
- 删除
- 更新

#### 7.3.4.2 当前目录下无文档时
1. 右侧展示提示文案：“当前目录下无需求文档”；
2. 在提示文案下方提供“立即上传”按钮；
3. 用户点击后，可从本地选择文件上传至当前目录；
4. 上传成功后，刷新当前文档表单展示。

### 7.3.5 文档预览
1. 点击“预览”后，在右侧窗口弹出文件预览区域；
2. 系统需支持以下格式的预览：
   - rp
   - Excel
   - Word
   - html
   - ppt
   - pdf
   - zip
3. 若文件格式不支持预览，则展示提示文案：
   - “不支持当前文件格式预览，请下载后在本地打开”

### 7.3.6 文档下载
1. 点击“下载”后，系统直接将当前文件下载至本地；
2. 下载完成后，不影响当前列表展示状态。

### 7.3.7 文档删除
1. 点击“删除”后，弹出确认对话框；
2. 对话框提示用户是否确认删除；
3. 用户确认后才执行删除；
4. 删除成功后，刷新当前目录下的文档列表或空状态展示。

### 7.3.8 文档更新
1. 点击“更新”后，用户可重新选择本地文件；
2. 新上传文件替代当前文件；
3. 更新成功后，刷新当前文档表单展示；
4. 更新时间应同步更新为最新更新时间。

### 7.3.9 立即上传
1. 当目录下无文档时，点击“立即上传”按钮；
2. 用户选择本地文件后，文件上传至当前选中的目录；
3. 上传成功后，页面从空状态切换为文档列表状态。

## 7.4 登录与退出功能

### 7.4.1 登录功能
1. 系统提供独立登录页面；
2. 用户需输入正确账号和密码后才能访问系统；
3. 当前默认账号信息如下：
   - 账号：admin
   - 密码：12345
   - 昵称：系统管理员
4. 登录成功后进入系统首页；
5. 若账号或密码错误，应提示用户登录失败。

### 7.4.2 登录后用户信息展示
1. 在系统页面右上角展示用户头像和昵称；
2. 头像默认取昵称首个字符；
3. 当前默认昵称为“系统管理员”。

### 7.4.3 退出登录
1. 用户点击右上角头像后，弹出下拉菜单；
2. 下拉菜单展示“退出登录”选项；
3. 用户点击“退出登录”后，退出当前登录状态；
4. 退出成功后返回系统登录页面。

### 7.4.4 登录态有效期
1. 用户登录成功后，登录状态持续 5 小时；
2. 在有效期内，用户可免重复登录访问系统；
3. 登录态过期后，系统应要求用户重新登录。

## 8. 数据字段定义

## 8.1 项目信息字段

| 字段名称 | 说明 | 是否必填 |
| --- | --- | --- |
| 项目名称 | 项目标识名称 | 是 |
| 版本号 | 项目当前版本信息 | 是 |
| 项目经理 | 项目负责人 | 是 |
| 需求部门 | 提出需求的部门 | 否 |
| 描述 | 项目说明信息 | 否 |
| 需求文档 | 与项目关联的需求文件 | 否，上传时按业务场景录入 |

## 8.2 文档信息字段

| 字段名称 | 说明 |
| --- | --- |
| 文档名称 | 文件名称 |
| 项目名称 | 所属项目 |
| 版本号 | 所属版本 |
| 项目经理 | 对应项目负责人 |
| 需求部门 | 对应需求部门 |
| 上传人 | 上传该文档的用户 |
| 更新时间 | 文档最新更新时间 |

## 9. 业务规则

1. 项目与需求文档应建立关联关系；
2. 文档目录层级固定为“项目名称 -> 版本号 -> 需求文档”；
3. 从项目概况进入需求文档管理时，必须自动定位到对应目录；
4. 删除类操作均需二次确认；
5. 文档上传、更新成功后，页面数据需立即刷新；
6. 登录用户在有效登录态内可持续访问系统；
7. 登录态超时后，需重新认证。

## 10. 非功能需求

## 10.1 易用性
- 菜单结构清晰，便于快速定位功能；
- 支持侧边栏展开与折叠，适配不同使用习惯；
- 常用操作按钮位置统一，降低学习成本。

## 10.2 安全性
- 未登录用户不可访问系统业务页面；
- 系统需校验账号密码后才允许登录；
- 登录态需具备有效期控制。

## 10.3 可维护性
- 项目信息与文档管理应结构清晰，便于后续扩展更多字段或角色权限；
- 文档目录结构应可持续维护，保证历史版本资料可追溯。

## 11. 验收要点

### 11.1 菜单与页面
- 可在左侧看到“项目管理”一级菜单及两个二级菜单；
- 侧边栏可折叠、展开；
- 页面在右侧以标签页形式打开。

### 11.2 项目概况
- 可对项目进行新增、查询、修改、删除；
- 列表可分页展示；
- 查询支持按项目名称、项目经理、版本号、需求部门模糊搜索；
- 文档入口可跳转并正确定位到文档目录。

### 11.3 需求文档管理
- 可看到目录树结构“项目名称 -> 版本号 -> 需求文档”；
- 有文档时展示文档表格；
- 无文档时展示空状态和“立即上传”按钮；
- 支持预览、下载、删除、更新操作；
- 删除前有确认提示；
- 更新或上传后列表自动刷新。

### 11.4 登录退出
- 使用 admin / 12345 可正常登录；
- 登录后右上角显示头像和昵称；
- 点击头像可看到“退出登录”；
- 退出后返回登录页面；
- 登录态可维持 5 小时。

## 12. 待确认事项

1. “项目版本”与“版本号”是否为同一字段，建议统一命名；
2. 需求文档是否允许一次上传多个文件，当前需求未明确；
3. 文档预览中提到支持 zip 预览，需进一步确认预览方式，是预览压缩包文件列表还是仅提示可下载；
4. 文档上传大小、数量限制及格式限制尚未明确；
5. 分页默认每页条数、排序规则尚未明确；
6. 是否需要记录项目创建时间、创建人、修改时间等审计字段，当前需求未明确。
