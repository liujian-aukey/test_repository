# 项目管理系统需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 系统名称 | 项目管理系统 |
| 文档类型 | 产品需求文档（PRD） |
| 当前版本 | V1.0 |
| 编写目的 | 将现有项目管理需求整理为结构化文档，作为后续产品设计、研发实现和测试验收依据 |

## 2. 项目背景

当前各产品项目相关资料（如产品原型、需求文档等）分散存放于不同位置，且不同项目使用的文件管理方式不一致，容易造成以下问题：

1. 项目资料归档口径不统一，难以统一检索和追踪；
2. 文档版本与项目版本对应关系不清晰，容易出现误用或遗漏；
3. 文件存储分散，增加管理成本，也不利于跨团队协作；
4. 不同管理系统并行使用，导致操作混乱、维护困难。

因此，需要建设一套统一的项目管理系统，对项目基本信息及需求文档进行集中管理。

## 3. 建设目标

1. 建立统一的项目台账，规范项目关键信息管理；
2. 建立项目与需求文档的关联关系，实现按项目和版本进行归档；
3. 提供统一的文档查看、上传、更新、删除、下载入口；
4. 通过登录鉴权保障系统访问安全；
5. 提升项目资料管理效率，降低查找、维护和交接成本。

## 4. 用户角色

当前版本默认仅支持一个管理员角色。

| 角色 | 账号 | 昵称 | 权限说明 |
| --- | --- | --- | --- |
| 系统管理员 | admin | 系统管理员 | 登录系统、管理项目信息、管理需求文档、退出登录 |

## 5. 适用范围

本期范围包含以下功能模块：

1. 菜单展示与系统主框架；
2. 项目管理 > 项目概况；
3. 项目管理 > 需求文档管理；
4. 登录与退出登录。

本期暂不包含：

1. 多角色、多租户权限管理；
2. 在线文档编辑；
3. 审批流、评论、消息通知；
4. 项目进度、任务拆解、工时统计等扩展项目管理能力。

## 6. 总体功能架构

系统采用二级菜单结构，当前仅配置一个一级菜单“项目管理”，其下包含两个二级菜单：

- 项目管理 > 项目概况
- 项目管理 > 需求文档管理

系统框架说明如下：

1. 左侧为侧边栏菜单区，支持折叠和展开；
2. 右侧为内容展示区；
3. 打开的菜单详情页以标签页形式展示；
4. 标签页名称取对应二级菜单名称；
5. 用户登录后进入系统主界面，未登录状态不可访问业务页面。

## 7. 详细需求

### 7.1 菜单展示功能

#### 7.1.1 页面结构

1. 系统一共分为二级菜单；
2. 一级菜单和二级菜单均在左侧侧边栏展示；
3. 侧边栏支持手动折叠和展开；
4. 点击二级菜单后，在右侧内容区域打开对应详情页；
5. 已打开页面以标签页形式展示；
6. 标签页名称为对应二级菜单名称；
7. 用户可在多个标签页之间切换浏览。

#### 7.1.2 菜单配置

当前菜单结构如下：

| 一级菜单 | 二级菜单 |
| --- | --- |
| 项目管理 | 项目概况 |
| 项目管理 | 需求文档管理 |

### 7.2 项目管理 > 项目概况

#### 7.2.1 功能目标

用于集中维护项目基础信息，并作为需求文档管理的入口和关联源。

#### 7.2.2 列表展示

1. 项目信息以表格形式展示；
2. 列表支持分页；
3. 表格字段包括：
   - 项目名称
   - 版本号
   - 项目经理
   - 需求部门
   - 描述
   - 需求文档
   - 操作

#### 7.2.3 查询功能

1. 表格上方提供“查询”区域；
2. 支持按以下条件进行模糊搜索：
   - 项目名称
   - 项目经理
   - 版本号
   - 需求部门
3. 支持点击查询按钮后刷新列表结果；
4. 查询结果需匹配分页逻辑联动展示。

#### 7.2.4 新增项目

1. 表格上方提供“新增”按钮；
2. 点击后弹出项目录入对话框；
3. 对话框内展示并录入以下信息：
   - 项目名称
   - 版本号
   - 项目经理
   - 需求部门
   - 描述
   - 需求文档
4. 需求文档通过上传文件的形式录入；
5. 已上传的需求文档在对话框中以标签块形式展示；
6. 必填项包括：
   - 项目名称
   - 版本号
   - 项目经理
7. 原始需求中“项目版本”与“版本号”表述重复，本文统一采用“版本号”字段定义；
8. 保存成功后关闭对话框，刷新项目概况列表。

#### 7.2.5 修改项目

1. 表格“操作”列提供“修改”按钮；
2. 点击后弹出编辑对话框；
3. 对话框需回显当前项目已录入信息；
4. 需求文档以标签块形式展示已有文件；
5. 可对项目信息进行修改并重新上传或维护需求文档；
6. 保存成功后关闭对话框，并刷新列表。

#### 7.2.6 删除项目

1. 表格“操作”列提供“删除”按钮；
2. 点击删除后弹出二次确认对话框；
3. 对话框需明确提示用户是否确认删除；
4. 仅在用户确认后执行删除；
5. 删除成功后刷新列表。

#### 7.2.7 需求文档跳转

1. 项目概况列表中的“需求文档”列需提供文档查看入口；
2. 点击后跳转至二级菜单“项目管理 > 需求文档管理”；
3. 跳转后需自动定位到对应项目、对应版本下的准确需求文档目录；
4. 定位完成后，右侧文档表单区域展示该目录下的文档内容。

### 7.3 项目管理 > 需求文档管理

#### 7.3.1 功能目标

用于按“项目名称 > 版本号 > 需求文档”层级统一管理需求文档，支持浏览、预览、下载、更新、删除和上传。

#### 7.3.2 页面布局

页面包含两个模块：

1. 左侧：需求文档目录树；
2. 右侧：当前选中目录对应的文档表单区域。

#### 7.3.3 目录树规则

1. 目录树按以下层级结构展示：
   - 项目名称
   - 版本号
   - 需求文档
2. 用户点击不同目录节点时，右侧文档表单区域需同步刷新；
3. 目录树应能够准确反映项目与版本对应的文档归档关系。

#### 7.3.4 文档表单展示规则

当用户选中某一目录时，右侧区域根据是否有文档展示不同内容。

##### A. 当前目录下有文档

1. 展示文档列表表格；
2. 表格字段包括：
   - 文档名称
   - 项目名称
   - 版本号
   - 项目经理
   - 需求部门
   - 上传人
   - 更新时间
   - 操作
3. “操作”列需提供以下按钮：
   - 预览
   - 下载
   - 删除
   - 更新

##### B. 当前目录下无文档

1. 右侧区域展示提示文案：“当前目录下无需求文档”；
2. 在提示文案下方提供“立即上传”按钮；
3. 点击后可选择本地文件上传至当前目录；
4. 上传成功后刷新当前文档表单展示。

#### 7.3.5 预览功能

1. 点击“预览”后，在右侧窗口弹出文件预览区域；
2. 需支持以下文件格式预览：
   - rp
   - Excel
   - Word
   - HTML
   - PPT
   - PDF
   - ZIP
3. 若当前文件格式不支持预览，则展示提示文案：
   - “不支持当前文件格式预览，请下载后在本地打开”

#### 7.3.6 下载功能

1. 点击“下载”后，系统直接将当前文件下载到用户本地；
2. 下载操作不改变当前列表状态。

#### 7.3.7 删除功能

1. 点击“删除”后弹出二次确认对话框；
2. 对话框明确提示是否确认删除该文件；
3. 仅当用户确认后才执行删除；
4. 删除成功后刷新当前目录下的文档列表。

#### 7.3.8 更新功能

1. 点击“更新”后，允许用户重新选择本地文件；
2. 新上传文件用于替代当前文件；
3. 更新成功后刷新当前目录下的文档列表；
4. 更新时间需同步更新为最新时间。

#### 7.3.9 上传功能

1. 当目录下无文档时，可通过“立即上传”入口上传文件；
2. 系统应将文件归档到当前选中目录；
3. 上传成功后，右侧区域切换为文档列表展示状态；
4. 若目录下已有文档，后续新增上传方式可根据设计方案扩展。

### 7.4 登录与退出功能

#### 7.4.1 登录

1. 系统需提供独立登录页面；
2. 用户只有输入正确账号和密码后才能访问系统；
3. 初始化账号信息如下：

| 字段 | 内容 |
| --- | --- |
| 登录账号 | admin |
| 登录密码 | 12345 |
| 账号昵称 | 系统管理员 |

4. 登录成功后进入系统首页；
5. 未登录用户访问业务页面时，应跳转至登录页面。

#### 7.4.2 登录态管理

1. 登录状态需维持 5 小时；
2. 登录态失效后，用户再次访问系统需重新登录；
3. 登录态有效期间，用户可正常访问系统功能。

#### 7.4.3 退出登录

1. 系统页面右上角展示用户头像和昵称；
2. 头像默认取昵称首个字符作为头像内容；
3. 点击头像后弹出下拉菜单；
4. 下拉菜单展示“退出登录”；
5. 点击“退出登录”后，系统需清除当前登录状态；
6. 退出成功后返回登录页面。

## 8. 关键业务规则

1. 项目与需求文档需建立明确关联关系，文档需按“项目名称 > 版本号”进行归档；
2. 项目概况中的“需求文档”入口必须能跳转到需求文档管理页并定位到准确目录；
3. 删除类操作必须经过二次确认；
4. 上传、更新、删除完成后，页面展示结果需立即刷新；
5. 登录鉴权是访问系统业务页面的前置条件；
6. 标签页名称固定使用二级菜单名称；
7. 侧边栏必须支持折叠与展开。

## 9. 主要数据项定义

### 9.1 项目基础信息

| 字段 | 说明 | 是否必填 |
| --- | --- | --- |
| 项目名称 | 项目唯一识别名称之一 | 是 |
| 版本号 | 项目当前版本信息 | 是 |
| 项目经理 | 项目负责人 | 是 |
| 需求部门 | 提出需求的部门 | 否 |
| 描述 | 项目说明信息 | 否 |
| 需求文档 | 关联上传的需求文档文件 | 否 |

### 9.2 需求文档信息

| 字段 | 说明 |
| --- | --- |
| 文档名称 | 上传文件名称 |
| 项目名称 | 所属项目 |
| 版本号 | 所属项目版本 |
| 项目经理 | 项目负责人 |
| 需求部门 | 需求归属部门 |
| 上传人 | 当前上传文件的用户 |
| 更新时间 | 文档最后一次上传或更新的时间 |

## 10. 非功能性要求

1. 页面结构清晰，保证项目与文档管理路径一致；
2. 文件操作反馈明确，上传、更新、删除后需给出成功或失败提示；
3. 对不支持预览的文件格式，需要给出明确提示文案；
4. 登录信息需具备基本安全控制，未登录不可进入系统；
5. 列表与目录切换响应应稳定，避免因状态错乱导致数据展示不一致。

## 11. 验收标准

### 11.1 菜单与框架

1. 左侧存在“项目管理”一级菜单；
2. 可展开查看“项目概况”和“需求文档管理”两个二级菜单；
3. 侧边栏支持折叠和展开；
4. 点击二级菜单后，右侧以标签页形式打开，标签名正确。

### 11.2 项目概况

1. 项目列表按表格分页展示；
2. 页面支持新增、查询、修改、删除；
3. 查询支持项目名称、项目经理、版本号、需求部门模糊搜索；
4. 新增和编辑使用对话框录入并支持需求文档上传；
5. 删除前有确认提示；
6. 需求文档列可跳转到需求文档管理页并正确定位到目录。

### 11.3 需求文档管理

1. 页面左侧展示目录树，右侧展示文档区域；
2. 目录树层级为“项目名称 > 版本号 > 需求文档”；
3. 目录下有文档时，展示文档列表及预览、下载、删除、更新操作；
4. 目录下无文档时，展示空状态文案及“立即上传”按钮；
5. 删除前有确认提示；
6. 预览不支持时显示指定提示文案；
7. 上传或更新后，列表及时刷新。

### 11.4 登录退出

1. 未登录不能进入系统业务页面；
2. 使用 admin / 12345 可以成功登录；
3. 登录后右上角正确展示头像和昵称；
4. 点击头像可看到“退出登录”；
5. 点击退出登录后返回登录页；
6. 登录状态可保持 5 小时。

## 12. 待确认事项

1. 原始需求中的“项目版本”和“版本号”是否为同一字段，本文暂统一为“版本号”；
2. “需求文档”在目录树中是固定目录名称，还是具体文件节点名称，当前按固定归档层级理解；
3. 需求文档预览支持格式中“rp”是否为业务侧特定文件类型，需在设计和开发阶段确认具体解析方案；
4. 本期仅给出管理员初始账号，后续是否需要扩展为多用户体系，需根据业务推广范围再评估。
