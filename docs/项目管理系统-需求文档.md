## 1. 概述

### 1.1 需求背景

在日常产品研发过程中，各个产品项目涉及的文件（如产品原型 `.rp`、需求文档 `.doc/.docx/.pdf`、相关附件等）分散存放于不同的存储介质与管理系统中（本地磁盘、云盘、IM 群共享、邮件附件等），存在以下问题：

1. 不同项目、不同团队间的文件存放规范不一致，导致后续检索困难；
2. 文件版本混乱，无法快速确认某一版本对应的需求文档；
3. 新成员接入项目时，信息同步成本高；
4. 缺乏统一的权限与访问入口，存在资料外泄或丢失风险。

为解决上述问题，建设一套统一的"项目管理系统"，集中管理各产品项目的基本信息及其对应的需求文档，实现"**一个项目、一套信息、一处归档**"的统一规范化管理。

### 1.2 产品目标

- **统一入口**：提供唯一的 Web 系统入口，集中维护项目信息与需求文档。
- **规范管理**：以"项目 → 版本 → 需求文档"的层级结构进行归档。
- **高效协作**：支持项目信息与需求文档的快速录入、检索、预览、下载、更新。
- **访问可控**：通过登录鉴权限制系统访问，保障资料安全。

### 1.3 名词解释

| 术语 | 说明 |
| --- | --- |
| 项目 | 产品研发的基本管理单元，对应一个产品线或一次独立交付 |
| 版本号 | 同一项目下的迭代版本标识（如 V1.0、V1.1） |
| 需求文档 | 承载产品需求说明的附件，可能为 `.rp/.doc/.docx/.xls/.xlsx/.ppt/.pptx/.pdf/.html/.zip` 等格式 |
| 目录树 | 需求文档页面左侧的层级树，结构为"项目名称 → 版本号 → 需求文档" |

### 1.4 适用范围

- 本文档仅描述项目管理系统 V1.0 的功能需求、交互规则与非功能性要求；
- 权限体系、组织架构、审批流转等进阶能力不在本期范围内（可在后续版本规划）。

## 2. 角色与使用场景

### 2.1 用户角色

本期仅设置单一系统管理员角色：

| 角色 | 账号 | 密码 | 昵称 | 权限描述 |
| --- | --- | --- | --- | --- |
| 系统管理员 | `admin` | `12345` | 系统管理员 | 登录系统、管理所有项目信息与需求文档（增删改查、上传、下载、预览等全部操作权限） |

> 后续版本将引入多角色与 RBAC 权限模型，本期暂不做区分。

### 2.2 典型使用场景

1. 项目经理新立项：录入项目基础信息并上传首版需求文档。
2. 产品经理迭代版本：修改项目信息，在同一项目下新增版本并上传新版需求文档。
3. 研发/测试成员查阅：根据项目名称/项目经理/版本号/需求部门搜索项目，查看并下载需求文档。
4. 从项目概况直接跳转到对应目录下预览需求文档。

## 3. 系统整体结构

### 3.1 菜单结构

系统采用"**左侧二级菜单 + 右侧标签页工作区**"布局，整体分为两级菜单：

```
一级菜单：项目管理
    └── 二级菜单：项目概况
    └── 二级菜单：需求文档管理
```

### 3.2 整体布局示意

```
┌────────────────────────────────────────────────────────────────────┐
│  Logo   系统名称：项目管理系统                    头像 ▾ 昵称      │  ← 顶部栏
├──────────┬─────────────────────────────────────────────────────────┤
│          │  [项目概况] [需求文档管理] ×  ← 标签页，可关闭、可切换 │
│  侧边栏  ├─────────────────────────────────────────────────────────┤
│  （可   │                                                         │
│  折叠/  │                  当前标签页内容区                       │
│  展开） │                                                         │
│          │                                                         │
└──────────┴─────────────────────────────────────────────────────────┘
```

### 3.3 通用交互规则

1. **侧边栏**：
   - 支持折叠与展开切换，折叠态仅显示图标，展开态显示"图标 + 文字"。
   - 侧边栏顶部提供折叠/展开按钮。
   - 侧边栏状态（折叠/展开）在同一登录会话中保持。
2. **标签页工作区**：
   - 每点击一个二级菜单，在右侧以标签页的形式打开对应内容页，标签页名称为"二级菜单名字"。
   - 如该二级菜单对应的标签页已打开，则直接激活定位到该标签页，不重复打开。
   - 标签页支持关闭（当前激活标签关闭后，默认激活相邻标签；若全部关闭则展示空状态）。
   - 标签页支持切换，切换时保留各标签页的页面状态（如分页页码、搜索条件、目录树选中节点等）。
3. **顶部栏**：右上角常驻展示当前登录用户的头像与昵称，详见 §5 登录退出。

## 4. 功能需求

### 4.1 项目概况（项目管理 → 项目概况）

#### 4.1.1 页面布局

```
┌─────────────────────────────────────────────────────────────┐
│  [查询区：项目名称 | 项目经理 | 版本号 | 需求部门]  [查询] [重置] [+ 新增] │
├─────────────────────────────────────────────────────────────┤
│  序号 项目名称 版本号 项目经理 需求部门 描述 需求文档 操作  │
│  ...                                                        │
│  ...                                                        │
├─────────────────────────────────────────────────────────────┤
│                                              分页控件        │
└─────────────────────────────────────────────────────────────┘
```

#### 4.1.2 列表展示

1. 以分页表格形式展示项目信息列表，默认每页 10 条，支持切换 10/20/50/100 条/页。
2. 表格列定义：

| 列名 | 说明 | 备注 |
| --- | --- | --- |
| 序号 | 自增序号 | 按当前页展示 |
| 项目名称 | 项目名称 | 必填 |
| 版本号 | 当前项目版本 | 必填 |
| 项目经理 | 项目经理姓名 | 必填 |
| 需求部门 | 提出需求的部门 | 选填 |
| 描述 | 项目描述 | 选填，超长显示省略号 + Tooltip 悬浮展示 |
| 需求文档 | 该项目已归档的需求文档入口 | 以标签块形式展示每个文档名；点击文档标签跳转至"需求文档管理"并定位到对应目录 |
| 操作 | 行内操作列 | 提供"修改"、"删除"按钮 |

3. 排序：默认按"创建时间倒序"展示。
4. 分页：默认展示总条数、当前页/总页数、上一页/下一页、页码跳转、每页条数切换。

#### 4.1.3 查询

1. 查询条件位于表格上方，支持以下 4 项作为**模糊搜索**条件（不区分大小写，允许任意组合）：
   - 项目名称
   - 项目经理
   - 版本号
   - 需求部门
2. 操作按钮：
   - **查询**：按当前输入条件过滤列表，列表回到第一页。
   - **重置**：清空所有查询条件并重新加载列表。
3. 若无匹配结果，表格内显示空状态"暂无匹配的项目信息"。

#### 4.1.4 新增项目

1. 入口：表格上方的"**+ 新增**"按钮。
2. 点击后弹出"新增项目"对话框，表单字段：

| 字段 | 控件 | 必填 | 校验规则 |
| --- | --- | --- | --- |
| 项目名称 | 文本框 | 是 | 1~50 字符 |
| 版本号 | 文本框 | 是 | 1~20 字符，建议格式 `Vx.y[.z]` |
| 项目经理 | 文本框 | 是 | 1~20 字符 |
| 需求部门 | 文本框 | 否 | ≤ 30 字符 |
| 描述 | 多行文本框 | 否 | ≤ 500 字符 |
| 需求文档 | 文件上传控件 | 否 | 支持多文件上传；单文件 ≤ 100MB；支持格式 `.rp/.doc/.docx/.xls/.xlsx/.ppt/.pptx/.pdf/.html/.zip`；已上传的文件以"**标签块**（文件名 + 删除图标）"形式展示，可点击删除图标移除未保存的文件 |

> 备注：原始需求中"项目名称、项目版本、项目经理、版本号为必填"，其中"项目版本"与"版本号"为同一字段，实际必填项为【项目名称、项目经理、版本号】三项。

3. 对话框按钮：
   - **取消**：关闭对话框，表单内容不保存。
   - **确定**：前端校验通过后提交保存；保存成功后关闭对话框并刷新列表（刷新后新项目应可见）。
4. 校验不通过时，在对应字段下方以红色文案提示具体错误；所有必填项未填或格式不合法时，禁用"确定"按钮或提交时统一提示。

#### 4.1.5 修改项目

1. 入口：表格行内"操作"列的"**修改**"按钮。
2. 点击后弹出"修改项目"对话框，复用新增对话框的表单字段与校验规则。
3. 对话框打开时：
   - 预填当前项目的所有已录入信息；
   - 需求文档区以"**标签块**"形式展示当前项目已归档的全部文档，每个标签块包含"文件名 + 删除图标"；
   - 支持在对话框中继续追加上传新文档，或点击标签块上的删除图标移除现有文档（移除需在点击"确定"后生效）。
4. 提交逻辑同"新增"。

#### 4.1.6 删除项目

1. 入口：表格行内"操作"列的"**删除**"按钮。
2. 点击后弹出二次确认对话框，文案：
   > 确认要删除项目「{项目名称}」吗？删除后该项目下的所有需求文档将一并被移除，且操作不可恢复。
3. 对话框按钮：
   - **取消**：关闭对话框，不执行删除。
   - **确定**：执行删除，成功后关闭对话框并刷新列表，右上角 Toast 提示"删除成功"。

#### 4.1.7 跳转需求文档

1. "需求文档"列的每个文档标签块提供一个"查看"入口（可整体点击或标签旁的小图标）。
2. 点击后的行为：
   - 若"需求文档管理"标签页未打开，则自动打开；
   - 若已打开，则激活该标签页；
   - 进入后自动在左侧目录树中定位到"项目名称 → 版本号 → 需求文档"对应节点，并在右侧表格中高亮该文档所在行。

### 4.2 需求文档管理（项目管理 → 需求文档管理）

#### 4.2.1 页面布局

页面分为左右两个模块：

```
┌────────────────────────┬────────────────────────────────────────────┐
│  需求文档目录（树）    │  文档表单（右侧）                          │
│                        │                                            │
│  ▸ 项目 A              │  文档名称 | 项目名称 | 版本号 | 项目经理 │
│    ▾ V1.0              │  | 需求部门 | 上传人 | 更新时间 | 操作   │
│      · 需求文档1.docx  │  ...                                       │
│      · 原型.rp          │                                            │
│    ▸ V1.1              │                                            │
│  ▸ 项目 B              │                                            │
│                        │                                            │
└────────────────────────┴────────────────────────────────────────────┘
```

- 左侧目录树支持宽度拖拽调整，默认占比 25%。
- 目录树支持搜索框，按文件/项目名称关键字快速过滤。

#### 4.2.2 目录树

1. **层级结构**：项目名称 → 版本号 → 需求文档。
2. 节点行为：
   - 点击"项目名称"或"版本号"节点：选中该节点，右侧展示该节点下的所有文档（含其子版本下的全部文档）。
   - 点击"需求文档"节点：选中该文档所在版本节点（即展开到最近版本级），右侧表格定位并高亮该文档行。
3. 目录数据来源于"项目概况"中维护的项目与需求文档，数据变动（新增/修改/删除/上传/更新）后目录树自动刷新。

#### 4.2.3 文档表单 —— 有文档场景

1. 表格列定义：

| 列名 | 说明 |
| --- | --- |
| 序号 | 按当前页自增 |
| 文档名称 | 文件名（含扩展名） |
| 项目名称 | 所属项目 |
| 版本号 | 所属版本 |
| 项目经理 | 该项目的项目经理 |
| 需求部门 | 该项目的需求部门 |
| 上传人 | 上传该文档的用户昵称 |
| 更新时间 | 最近一次上传/更新的时间，格式 `YYYY-MM-DD HH:mm:ss` |
| 操作 | 预览 / 下载 / 删除 / 更新 |

2. 默认按"更新时间倒序"排序，支持分页（同 §4.1）。

##### 4.2.3.1 预览

1. 点击"预览"按钮，在右侧打开一个预览窗口（抽屉或大尺寸弹窗），窗口标题为文件名。
2. 支持以下格式的在线预览：
   - `.rp`（Axure 原型）
   - `.xls`、`.xlsx`（Excel）
   - `.doc`、`.docx`（Word）
   - `.html`
   - `.ppt`、`.pptx`（PowerPoint）
   - `.pdf`
   - `.zip`（展示压缩包目录结构，支持进入子目录浏览；子文件本身不强制预览）
3. 若为不支持的格式（或预览服务不可用），窗口中居中显示文案：
   > 不支持当前文件格式预览，请下载后在本地打开
   
   并在文案下方提供"下载"按钮。
4. 预览窗口支持关闭按钮，关闭后返回文档表单。

##### 4.2.3.2 下载

点击"下载"按钮，将文件原始二进制直接下载到本地（使用原文件名）；下载失败时 Toast 提示"下载失败，请稍后重试"。

##### 4.2.3.3 删除

1. 点击"删除"按钮，弹出二次确认对话框，文案：
   > 确认要删除文档「{文档名称}」吗？删除后文件将从系统中移除，且操作不可恢复。
2. 点击"确定"后执行删除，成功后刷新当前目录下的文档表单与左侧目录树，Toast 提示"删除成功"。

##### 4.2.3.4 更新

1. 点击"更新"按钮，弹出本地文件选择器。
2. 选择本地文件后：
   - 使用新文件**替换**当前文档（保持原目录位置，但文档名称、上传人、更新时间以新文件为准）；
   - 上传成功后刷新文档表单与目录树；
   - 上传失败时 Toast 提示具体错误，原文档保持不变。
3. 新文件需符合 §4.1.4 中需求文档的格式与大小限制。

#### 4.2.4 文档表单 —— 无文档场景

当选中的目录节点（项目或版本）下无任何需求文档时：

1. 文档表单区域居中展示空状态文案：
   > 当前目录下无需求文档
2. 文案下方提供"**立即上传**"按钮。
3. 点击按钮弹出本地文件选择器，支持选择一个或多个文件（格式与大小限制同 §4.1.4）。
4. 上传成功后：
   - 文档归档到当前选中的目录节点下（项目/版本）；
   - 右侧自动切换为"有文档场景"的表格形式；
   - 左侧目录树同步刷新。
5. 若选中的是"项目名称"级节点但该项目尚未建立任何版本，则"立即上传"需引导用户在"项目概况"中先补充版本号（弹出提示"请先在'项目概况'中录入该项目的版本号"）。

### 4.3 登录与退出

#### 4.3.1 登录页面

1. **页面构成**：系统名称/Logo、登录表单、版权信息。
2. **表单字段**：

| 字段 | 控件 | 必填 | 校验 |
| --- | --- | --- | --- |
| 账号 | 文本框 | 是 | 非空 |
| 密码 | 密码框（默认掩码、可切换显隐） | 是 | 非空 |

3. 提交按钮："**登录**"。
4. **登录校验**（V1.0 硬编码）：
   - 账号：`admin`
   - 密码：`12345`
   - 昵称：`系统管理员`
5. **校验结果**：
   - 成功：跳转系统首页（默认打开"项目概况"标签页），并在顶部栏展示头像与昵称；
   - 失败：表单下方红色文案提示"账号或密码错误，请重新输入"，表单清空密码字段。
6. 未登录用户直接访问系统内任何页面时，一律重定向到登录页。

#### 4.3.2 登录态保持

1. 用户成功登录后，登录状态**保持 5 小时**。
2. 5 小时内无论是否有页面活动，登录态始终有效；超过 5 小时后，下一次操作（接口请求或页面刷新）一律重定向到登录页，并提示"登录已过期，请重新登录"。
3. 登录态信息存储建议：服务端签发 Token（含过期时间），客户端使用 `Cookie (HttpOnly)` 或 `localStorage` 持久化。
4. 同一浏览器多标签共用同一登录态。

#### 4.3.3 已登录状态下的顶部栏

1. 顶部栏右上角常驻展示：
   - **头像**：默认使用"**昵称首字符**"作为头像（即 `系` 字），背景色可采用系统主题色的浅色填充；
   - **昵称**：展示登录用户的昵称（本期为"系统管理员"）。
2. 点击头像区域，弹出下拉菜单，包含一项：
   - **退出登录**

#### 4.3.4 退出登录

1. 点击"退出登录"后：
   - 清除本地 Token/会话信息；
   - 通知服务端使 Token 失效（调用退出接口）；
   - 跳转到登录页面，并提示"已退出登录"。
2. 退出后再次访问系统内任何 URL 均需重新登录。

## 6. 非功能性需求

### 6.1 性能

- 项目列表、文档列表首屏加载 ≤ 2 秒（千条数据规模内）。
- 目录树展开、节点切换响应 ≤ 300ms。
- 单文件上传/下载峰值速率不低于带宽的 80%。

### 6.2 兼容性

- 浏览器：Chrome ≥ 90、Edge ≥ 90、Firefox ≥ 90、Safari ≥ 14。
- 分辨率：最低适配 1366×768；推荐 1920×1080。
- 本期暂不要求适配移动端。

### 6.3 安全

- 登录密码传输采用 HTTPS；服务端存储应加盐哈希（后续版本强化）。
- 接口需校验 Token 有效性；失效后统一返回 401，并由前端重定向到登录页。
- 文件上传需进行扩展名白名单校验与大小限制，避免恶意文件上传。
- 防 XSS/CSRF：对所有用户输入进行转义；关键操作接口开启 CSRF Token 校验。

### 6.4 可用性

- 所有破坏性操作（删除、覆盖更新）均需二次确认。
- 所有操作结果（成功/失败）均需通过 Toast 或 Dialog 明确反馈。
- 表单字段应具备即时校验与错误提示。

### 6.5 可维护性

- 前后端分离，接口采用 RESTful 风格。
- 关键操作需记录日志（登录、登出、项目增删改、文档上传/更新/删除），便于审计。
